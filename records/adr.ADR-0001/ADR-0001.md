# ADR-0001: Purpose — Build Offline-First PWAs for All Shipped Apps

## Context
OurBox is browser-first. Shipped apps run under tenant origins and use local persistence with opportunistic sync. See ADR-0014 and RFC-0002 for access-mode behavior.

Critical architectural constraint: shared tenant origin + shared local replica.

Supported tenant-origin patterns:
- local-only mode: `http://<tenant_id>.local/...`
- public custom-domain mode: `https://<tenant_id>.<box-host>/...`

Within one tenant origin, shipped apps share a local tenant replica. Local-only and public custom-domain mode for the same tenant are different origins.

## Decision
Shipped apps SHALL remain browser-first, offline-capable applications with:
- local persistence via PouchDB,
- opportunistic sync while box is reachable,
- tenant-origin routing with app path semantics.

Mode-scoped behavior:
1. Public custom-domain mode provides full installable-PWA posture and reopen-offline capability after first successful load.
2. Local-only mode is HTTP-only local web mode with local data continuity, without guaranteed equivalent installability/reopen-offline behavior.
3. Transport/security posture differs by mode; local-only mode has no TLS transport guarantees and may show insecure-transport browser UI.
4. Operate within a tenant origin in both supported patterns.

## Consequences
- Product documentation and requirements use explicit mode scoping for installability/offline claims.
- Architecture and app requirements preserve browser-first continuity in both modes while distinguishing HTTPS PWA guarantees from HTTP local-mode guarantees.
